# KOOK RAG 챗봇 Scope 정의 (근거 기반)

이 문서는 `backend/data/rag-source/*.txt`(KB 원문), `backend/FOOK_rag_chatbot.py`의
`SYSTEM` 프롬프트·`SERVING_G`/`food_lookup_answer()` 설계, `backend/FOOK_adjust_levers.py`의
5대 영양소(K/P/Na/protein/energy) 프레임워크(읽기 전용, 맥락 참고), 그리고 기존
`backend/evaluation/rag_eval_questions_v2.json`의 30개 positive 문항이 실제로 무엇을
in-scope으로 취급해왔는지를 근거로 삼는다. 추측이 아니라 위 4가지를 직접 읽고 도출했다.

## 1. SYSTEM 프롬프트가 선언한 제품 범위

`FOOK_rag_chatbot.py` 182-189행:
> "너는 혈액투석 환자를 위한 영양 정보 안내 챗봇이다. 반드시 아래 [참고 자료]에 있는 내용만
> 근거로 답하고 ... 특정 환자의 검사 수치나 약물처럼 개인별로 다른 판단이 필요한 질문에는
> 일반적인 원칙만 설명하고, 반드시 담당 의료진·영양사와 상담하도록 안내해라."

명시적으로 두 가지를 선언한다: (1) 대상은 **혈액투석 환자**, (2) 주제는 **영양 정보**.
그리고 약물(medication)은 "개인별 판단이 필요한 질문"으로 명시적으로 별도 취급되어
일반 원칙 설명 + 의료진 상담 유도로 제한된다 — 즉 SYSTEM 프롬프트 자체가 이미 "약물은
이 챗봇이 직접 판단할 영역이 아니다"라고 선을 긋고 있다.

## 2. KB 원문이 실제로 다루는 범위 (읽은 그대로)

`backend/data/rag-source/`의 4개 문서(혈액투석_영양식생활관리_2권 7234줄,
콩팥병_환자를_위한_안내서 3772줄, 만성콩팥병_환자_식사요법 734줄, 혈액투석환자를_위한_간식
88줄)의 목차를 grep으로 직접 확인한 결과, KB는 순수 영양 수치(칼륨/인/나트륨/단백질/수분)
보다 훨씬 넓다. 특히 `혈액투석_영양식생활관리_2권`(II장, "혈액투석 환자를 위한 영양-식생활
관리")의 목차 41개 챕터 중 실제로는:
- 영양/식이 직결: 8/9/10/12(단백질/열량/지방/무기질), 15~26(먹는 양, 인·칼륨 수치,
  입맛, 열량, 외식, 저염식), 27~31(과일/채소/간식/식단/레시피) 등 — **명백히 in-scope**.
- 영양과 무관한 투석 시술/장비: 3("perm 도관을 어떻게 관리하나요?"), 4("혈액투석접근로를
  어떻게 관리하나요?"), 38("투석혈관이 자꾸 막혀요") — 혈관/도관 관리는 시술·간호 영역.
- 삶의 질/정신건강: 11("우울해요"), 12("불면증이 심해요"), 14("임신이 가능한가요"),
  39(여행) — 영양이 아니라 생활 전반.
- 운동: 6~10 — 운동 처방 영역.

`FOOK_build_rag_kb.py`의 이번 태스크 이전 변경사항(목차-노이즈 필터, TOC_LINE_RE)은
목차/쪽번호 형태의 **문단**만 제거하며, 챕터 **본문**은 주제와 무관하게 전부 청크로
남는다(직접 확인: `data/FOOK_rag_kb.json`의 536개 청크 중 "perm 도관"(2건),
"혈액투석접근로"(1건), "불면증"(3건), "임신이 가능"(1건), "비용"(14건), "수가"(10건) 등이
실제로 존재). 즉 **KB에 실제로 검색 가능한 콘텐츠가 있다고 해서 그것이 자동으로
"이 챗봇의 scope 안"이라는 뜻은 아니다** — KB는 책 전체를 통째로 청킹한 부산물이고,
챗봇의 선언된 목적(SYSTEM 프롬프트, §1)은 그보다 좁다. 이 괴리 자체가 §4의 핵심
판단 근거다.

## 3. food_lookup_answer()가 설계된 목적

`SERVING_G`/`_grade()`/`find_food()`(195-296행)는 "특정 재료 하나를 먹어도 되는가"라는
질문에 영양DB 실측치(칼륨/인/나트륨)로 답하도록 설계돼 있다 — 순수 영양 성분 조회이며,
약물이나 시술과 무관하다. `FOOK_adjust_levers.py`(1-11행 docstring)의 5대 영양소
(칼륨/인/나트륨/단백질/열량) 레버 프레임워크와 정확히 같은 축(K/P/Na/protein/energy)을
공유한다 — 이 서비스 전체(`FOOK_adjust_levers.py`의 끼니 생성 + `FOOK_rag_chatbot.py`의
질의응답)가 일관되게 이 5개 영양소를 중심으로 설계돼 있다는 것이 이번 조사에서
재확인된 사실이다.

## 4. 결론: IN_SCOPE / OUT_OF_SCOPE 정의

**IN_SCOPE** (아래 중 하나 이상에 해당):
1. 혈액투석/만성콩팥병 환자의 5대 영양소(칼륨·인·나트륨·단백질·수분/열량) 섭취 관리 —
   수치 기준, 고/저 식품, 조리법(저염 조리, 칼륨 용출법 등), 특정 재료 섭취 가부.
2. 식사/간식/외식 구성과 레시피.
3. 위 영양 관리와 직결된 임상 지표·증상 — 알부민(영양 지표), 부종·체중증가(수분/나트륨
   결과), 요독성 가려움증·뼈 건강(인/칼슘 관리와 직결), 대사성 산증(단백질/열량과 연관).
   근거: 기존 v2 eval set이 이미 이들을 positive(alb1, itch1, bone1, acidosis1)로
   테스트하고 있고, KB 본문이 실제로 영양 관리 맥락에서 이 주제들을 다룬다(순수 증상
   백과사전이 아니라 "왜 생기고 식이로 뭘 할 수 있는가" 서술).
4. 만성콩팥병/투석에 대한 일반 교육 콘텐츠(질병 개요, 단계, 콩팥 기능) — §5에서 논의.

**OUT_OF_SCOPE**:
1. 일반 상식·잡담·타 도메인(날씨/스포츠/코딩/연애상담 등) — 기존 21개 OOS 문항 대부분.
2. **의학적으로 그럴듯하지만 투석-영양과 다른 치료 영역** — 감기약, 진통제, 수면제 등
   일반 약물 복용, 당뇨병 인슐린 용량, 암 항암치료/화학요법 부작용 관리, 갑상선/혈압
   약물 복용 시점 등. SYSTEM 프롬프트가 명시적으로 "약물은 개인별 판단 필요 → 의료진
   상담"으로 선을 그은 영역과 정확히 겹친다.
3. **투석 관련이지만 영양이 아닌 시술/장비/행정 영역** — 투석 도관(perm 도관)·혈관통로
   관리, 투석 기계 작동 원리, 투석 비용/보험 적용, 투석 스케줄 조정. KB에 관련 문장이
   실제로 존재해 검색 게이트를 우연히 통과할 수 있지만(§2), SYSTEM 프롬프트의 선언된
   목적(영양 정보) 밖이라고 판단한다 — **판단 근거는 KB 존재 여부가 아니라 제품
   선언(§1)**.

## 5. 경계 사례 (명시적 판단)

- **일반 CKD 교육 콘텐츠(ckd1/ckd2/early1: "만성콩팥병 단계", "콩팥이 하는 일", "초기
  증상")**: 엄밀히는 "식이 관리"가 아니라 "질병 교육"이다. 그러나 (a) 기존 v2 eval set이
  이미 이를 positive/rag로 명시 테스트하고 있어 룰을 새로 만드는 게 아니라 기존 제품
  판단을 존중하는 것이고, (b) 이 정보가 없으면 뒤이은 식이 지침(왜 칼륨을 제한하는지 등)의
  맥락을 이해할 수 없어 실질적으로 영양 상담의 전제 지식에 해당한다고 보아 **IN_SCOPE로
  판단**한다.
- **여행 준비(trip1: "투석 받는데 여행 가려면 미리 뭘 준비해야 해요?")**: 순수 물류/일정
  질문에 가깝지만 기존 eval set이 이미 positive로 다루고 있으므로 이번 작업에서 뒤집지
  않는다(원 eval set 문항 내용은 불변 제약). 다만 새로 추가하는 하드케이스에서는 이와
  유사한 "투석 스케줄/장비/보험" 류를 명시적으로 OUT_OF_SCOPE로 신규 정의해 이 경계를
  더 좁게 긋는다(4-③) — 즉 "이미 검증된 기존 positive는 그대로 두되, 이번에 새로
  긋는 경계선은 더 보수적으로 잡는다"는 절충.
- **복막투석(PD) 관련 질문**: KB 목차에 "복막투석"이 언급되지만 챗봇/서비스명(KOOK,
  혈액투석 식단 AI)과 SYSTEM 프롬프트 모두 혈액투석(HD) 환자를 명시 대상으로 한다.
  이번 작업 범위 밖이라 별도 eval 문항을 만들지 않았지만, 향후 스코프 확장 시 재검토
  대상으로 남긴다.
- **당뇨/고혈압처럼 동반질환 자체를 언급하되 실제 질문 내용은 투석-영양인 혼합 의도
  질문** ("당뇨도 있는데 칼륨 조절은 어떻게 해요?"): 동반질환 언급 자체는 OUT_OF_SCOPE
  신호로 취급하지 않는다 — 실제로 답변 가능한 내용(칼륨 조절)이 명백히 IN_SCOPE이기
  때문. 이는 §6 mixed-intent 섹션의 핵심 판단 기준이다.
