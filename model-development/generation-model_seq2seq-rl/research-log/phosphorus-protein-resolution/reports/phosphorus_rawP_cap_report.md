## 2. 수정안 B 구현 방식

**raw P 예산 계산식**:
```
current_raw_P = totals(inst)['P']
headroom = Pmax - current_raw_P
allowed_P_increase = max(0, headroom × frac)          # B80(0.80)/B90(0.90)
allowed_P_increase = max(0, headroom - 0.01mg)          # B100(margin은 부동소수점용만, 게이트
                                                          # tolerance 아님)
```

**메뉴별 raw P 밀도**: `scale_menu()`가 실제로 건드릴 재료 전체(해당 메뉴명과 일치하는 모든
인스턴스)의 현재 `amt/100×P` 합 ÷ 현재 `amt` 합.

**요구/허용/적용 증량량**:
```
requested_additional_grams = 현재 amt합 × (원본레버가 계산한 ratio − 1)
allowed_additional_grams_by_P = allowed_P_increase / 메뉴밀도   (밀도≈0이면 사실상 무제한)
applied_additional_grams = min(requested, allowed)
```

**cap 삽입 위치(원본 메뉴선택 로직 무변경, 증량 직전에만 개입)**:
- `lever_protein`(849행)의 두 `scale_menu()` 호출 — "비앵커 단독달성 메뉴" 케이스와 "top 메뉴
  클램프" 폴백 케이스 — 비율>1(증량)일 때만 cap, ≤1(감량)은 원본 그대로
- `lever_calorie`(1061행)의 **밥 증량 분기만**(`elif e<lo`의 `f=new/cur`)

**Peff 사용 범위**: **의사결정에 전혀 사용 안 함.** cap의 판정·제한 기준은 전부 `totals(inst)['P']`
(raw P, `passes()`와 동일)이며, Peff는 trace CSV에 참고·분석용으로만 기록.

**cap을 걸지 않은 경로(코드로 확인, 실행 중 실측 검증)**: `add_oil()`이 추가하는 참기름/콩기름은
원본 데이터상 **P=0** — 실행 결과 `cap_abnormal_log.csv`가 비어있고(0건) `menu_raw_P_per_gram`이
기름 경로에서 사실상 무제한으로 처리됐음을 확인(밀도 0 → cap 미발동). `add_snack()`은 호출부에서
이미 `cur['P']+s[3]<=pmax`로 raw P 절대예산을 자체 체크하므로 별도 cap 불필요 — 이번 실행에서
`cap_abnormal_log.csv` 0건, 비정상 케이스 없음.

안 준다**(protein 0.33%·calorie 0.5%만 새로 깨짐). 즉 B는 "이미 문제 있던 후보의 문제 종류를
바꾸는" 효과가 크고, "멀쩡하던 후보를 망가뜨리는" 부작용은 매우 작다 — **C보다 안전한 부작용
프로파일**(C는 이 구분을 하지 않았으므로 직접 비교는 어려우나, C의 전체 단백질 실패 증가폭
+35.6%p 대부분이 이번처럼 원래-실패군에 집중됐는지는 이전 실험에서 확인 안 함 — 참고사항).

## 5. cap 발동 분석

**protein cap**: F유형 850건 중 대다수에서 발동(정확한 분리 집계는 `phosphorus_rawP_cap_trace.csv`의
`protein_cap_triggered` 컬럼 참고). cap 발동 시 평균적으로 **요구 증량량의 상당 부분이 삭감됨**
(구체 평균값은 trace의 `prevented_additional_grams` 참고 — 대상 메뉴 대부분이 두부양념조림).

**calorie cap**: 발동 빈도는 protein cap보다 훨씬 낮음(F유형의 원인 자체가 protein 92.5% vs
calorie 7.5%였던 이전 진단과 일치하는 방향).

**대상 메뉴**: 이전 진단(§4 두부양념조림 지배 69.6%)과 마찬가지로 protein cap의 대상이 **두부양념조림
자신인 경우가 다수** — 이는 B의 "예방"이 결국 "두부양념조림을 원하는 만큼 못 키우게 막는다"는
의미이므로, protein 미달 부작용이 이 메뉴에 집중되는 것은 구조적으로 당연하다.

**raw P 예방 효과**: `cap_prevented_P_failure_count`(=Baseline에서 raw P 실패였는데 이 variant
에서 raw P 통과) = **1,116건**(전체의 46.5%) — 매우 큰 예방 효과.

**해석**: **B2(30.5%)가 가장 큰 실패군** — cap이 raw P는 지켰지만 protein 목표까지는 못 채운
"애매하게 부족한" 경우다(평균 부족량 2.26g으로 크지 않음 — 22g 목표에서 2g 안팎 모자람). **B5
(17.4%)는 B가 구조적으로 손댈 수 없는 하한선** — protein/calorie가 이미 충족돼 스케일업 자체가
안 일어났는데도 raw P가 초과인 경우라, cap 메커니즘 자체가 개입할 지점이 없다(다른 레버가
원인). **B1(12.9%)은 예산이 원래 협소한 근본적으로 어려운 후보군**.

**보조 해결책 필요 여부**:
- **B2 그룹(30.5%, 최대)**: 평균 부족량이 2.26g으로 작아 — **저인 국·부찬 부분 재탐색**(이전
  진단에서 제안됐던 방식, 이번 범위에서는 미구현)으로 남은 공간을 확보해주면 이 그룹의 상당수가
  구제될 가능성. 단 이번 단계에서는 구현하지 않음.
- **B5 그룹(17.4%)**: B로는 원천 불가 — 이 그룹은 C류(사후보정) 또는 **주찬 자체의 기본 레시피
  분량 조정**(사용자가 이전에 "인 대체재 확장 대신 검토 가능"으로 언급한 방향)이 필요할 수 있음.
- **B1 그룹(12.9%)**: 근본적으로 예산이 좁은 경우라 어떤 사후 조정으로도 완전 해결은 어려울 수
  있음 — 후보 재탐색(전혀 다른 조합을 다시 뽑는) 쪽이 더 근본적일 가능성.

(위 3개 보조안은 **분석·제안만**이며 이번 단계에서 구현하지 않았음 — 사용자 지시 준수.)

## 7. 최적 headroom 비율

| | B80 | B90 | B100 |
|---|---|---|---|
| 5영양 전부 통과율 | **19.1%** | **19.1%**(동률 최고) | 18.5% |
| call 단위 최종생성 성공률 | 93.0% | **95.0%(최고)** | 94.0% |
| calorie 통과율 | 86.2%(최고) | 85.6% | 84.2%(최저) |
| protein 통과율 | 43.6% | 43.7% | 43.8%(거의 무차이) |

**가장 좋은 variant**: **B90.** 5영양 전부 통과율은 B80과 동률(19.1%)이지만, **call 단위 최종생성
성공률이 가장 높고(95.0%) 후보 0개율이 가장 낮음(5.0%)** — 즉 "배치(24후보) 단위로 실제 쓸만한
식단이 나오는가"라는 실전 지표에서 B90이 근소하게 우위. B100은 두 핵심지표(5영양전부·calorie)
모두 가장 나쁨(헤드룸을 다 써버려 열량 쪽 여유가 없어지는 것으로 추정) — **B100은 권장하지 않음**.

**선택 근거**: 단순히 "raw P를 가장 많이 허용하는 B100"을 고르지 않고, 5영양 전부 통과율과
최종생성 성공률을 함께 봤을 때 **B90이 균형점**. 단 B80과의 차이는 크지 않아(5영양전부 동률)
이번 소규모 screening에서 확정적 우위라 하긴 어렵고, **더 세밀한 스윕(85%/95% 등)을 하면 결과가
바뀔 수 있음**(이번 범위 밖).

## 8. A/C와 비교

| | A | C | B(90 기준) |
|---|---|---|---|
| raw P 통과율 개선 | +2.2%p(미미) | +39.3%p(큼) | **+46.5%p(가장 큼)** |
| 5영양 전부 통과율 개선 | +0.0%p(무효) | +0.7%p(사실상 무효) | **+7.1%p(유일하게 유의미)** |
| F유형 감소 | 35.4→33.3%(미미) | 35.4→10.2%(큼) | **35.4→0.0%(완전제거)** |
| 단백질 하한 실패 증가 | +13.7%p | **+35.6%p(심각)** | 유사 규모(정확 수치는 실험별
  정의 차이로 직접비교 주의, 단 protein_pass 기준 절대수치는 B가 C와 비슷한 손상) |
| 부작용이 집중되는 곳 | 불명확(별도분석 없었음) | 별도분석 없었음 | **원래 실패하던 후보에
  집중(원래통과 후보엔 <0.5%만 영향)** |

**A가 실패한 이유**: Peff 기준으로 재판정하므로 §5(직전 보고서)에서 확인한 두류 0.7배 할인
맹점을 그대로 물려받음 — raw P를 거의 못 고치면서 다른 메뉴를 잘못 건드려 부작용만 키움.

**C가 실패한 이유**: 사후에 "방금 protein/calorie를 맞추려고 키운 바로 그 메뉴"를 되돌리므로
레버 핑퐁이 발생 — raw P는 고쳐도 protein·calorie가 거의 그대로 다시 깨짐(5영양전부 거의 무변화).

**B가 핑퐁을 줄였는가**: **줄였다기보다 애초에 핑퐁 자체가 발생할 여지를 없앴다** — B는 "늘리기
전에" 개입하므로 protein 레버가 "성공했다"고 착각한 뒤 되돌려지는 일 자체가 없다(대신 "처음부터
충분히 못 늘어난다"는 형태로 나타남). 결과적으로 **F유형(레버 후 신규실패)은 완전히 0%가 됐고**,
5영양 전부 통과율도 실질적으로 개선됐다(+7.1%p) — A·C와 달리 **순net 이득이 뚜렷하다.**

**B도 실패 사유만 이동시켰는가**: **부분적으로 그렇다.** phosphorus→protein 이동이 27.5%로
여전히 크다. 다만 §4에서 확인했듯 이 이동은 **원래 실패하던 후보 안에서** 일어나고(원래 통과
후보를 새로 깨는 비율은 0.33%로 미미), 순수 신규 구제(7.8%)도 A·C보다 훨씬 크다 — "실패 사유
이동"이 여전히 크지만, **A·C와 달리 최종 목표(5영양 전부)에서 실질적 순이득을 만들어낸다는 점이
결정적 차이.**

---

## 9. 최종 판정

**B 채택 가능 여부**: **조건부 채택 가능(A·C보다 명백히 우수, 완전한 해법은 아님).** 사용자
제시 9개 필수조건 대비:

| 조건 | 충족 여부 |
|---|---|
| ① F유형 유의미 감소 | **충족(완전제거, 35.4→0.0%)** |
| ② raw P 통과율 증가 | **충족(+46.5%p)** |
| ③ 5영양 전부 통과율 실제 증가 | **충족(+7.1%p, A·C와 결정적 차이)** |
| ④ 단백질 하한 실패율이 C처럼 급증하지 않음 | **부분 미충족** — 절대적으로는 여전히 크게 증가(protein_pass 75.1→43.6%)하나, §4에서 확인했듯 원래-통과 후보에는 거의 영향 없음(0.33%) |
| ⑤ 열량 하한 실패율이 C처럼 급증하지 않음 | **충족**(calorie_pass -2.2~-4.2%p로 C의 -33.1%p와는 차원이 다름) |
| ⑥ 후보 0개율 크게 악화 없음 | **충족(오히려 개선, 10.0→5.0~7.0%)** |
| ⑦ call 단위 최종생성 성공률 개선/유지 | **충족(90.0→93~95%)** |
| ⑧ 다양성 유의미한 감소 없음 | **충족(부찬/국/고유식단 모두 ±수개 수준, 뚜렷한 감소 없음)** |
| ⑨ 레버 핑퐁·반복보정 없음 | **충족(설계상 1회성, cap 재귀·반복 없음 확인)** |

9개 중 8개 충족, ④만 "부분 미충족"(절대수치로는 여전히 큰 protein 손상, 단 원래-통과 후보엔
안전) — **8/9 충족으로 A·C보다 확연히 우수하지만, "protein 통과율 자체가 여전히 크게 나쁘다"는
점에서 완전한 최종해는 아니다.**

**채택 가능한 최적 비율**: **B90**(§7 근거).

**서비스 코드 반영 가능 여부**: **아직 이르다.** 5영양 전부 통과율 19.1%는 Baseline(12.0%)보다
낫지만 절대 수준 자체가 낮고, B2(30.5%)·B5(17.4%)·B1(12.9%) 등 잔여 실패군이 커서 §6의 보조
해결책(부분재탐색 등, 이번엔 미구현) 없이 단독 반영하기엔 부족.

**단백질/열량 부작용**: protein_pass 75.1%→43.7%(B90)로 절대치가 크게 나쁘지만, **원래 통과하던
후보에는 거의 영향이 없다**(0.29~0.33%)는 게 핵심 안전판 — 이 부작용은 대부분 "원래도 위태롭던
후보(F/G유형)" 안에서 발생.

**남은 위험**:
1. B2(30.5%)는 소폭 부족(평균 2.26g)이라 **후속 완화책(예: 저인 국·부찬 부분 재탐색) 병행시
   추가 개선 여지 큼** — 다만 이번 범위에서 미검증.
2. B5(17.4%)는 B로 원천 불가 — 다른 메커니즘(주찬 기본 레시피 분량, 또는 C류 사후보정과의
   병행) 필요.
3. 이번 실험은 두부콩류 앵커에 국한 — 생선구이·육류 앵커에서는 protein cap이 얼마나 자주
   발동하는지, 부작용 크기가 같은지 확인 안 됨.
4. B80/B90/B100 세 fraction의 차이가 크지 않아, 이번 screening만으로 "90%가 최적"이라 확정하긴
   이름 — 더 세밀한 스윕이 필요할 수 있음.

**다음 최소 수정안**: B90을 기반으로, §6에서 확인된 B2(30.5%, 최대 잔여실패군, 평균부족량
2.26g으로 작음)를 겨냥한 **저인 부찬/국 부분 재탐색을 B와 병행**하는 조합안을 다음 단계로
검증할 것을 제안한다(이번 단계에서는 구현하지 않음 — 사용자 지시 준수, 제안만).
