## 🩺 문제 정의

혈액투석 환자는 매 끼니마다 단순히 저염식 여부만 확인하는 것이 아니라
**열량·단백질·칼륨(K)·인(P)·나트륨(Na)**을 함께 고려해야 합니다.

한 영양소를 줄이기 위한 조정이 다른 영양소의 부족이나 초과로 이어질 수 있어,
환자는 결국 식사 전마다 **“무엇을 얼마나 먹어야 하는지”** 판단해야 합니다.

기존 식이관리 서비스가 섭취 후 기록과 영양정보 확인에 집중했다면,
FOOK은 다음 질문에서 출발했습니다.

> **먹은 뒤 확인하는 것이 아니라, 먹기 전에 기준에 맞는 한 끼를 만들 수 없을까?**

## 💡 Solution

FOOK은 사용자의 신체정보와 식사기록을 바탕으로 개인별 영양 기준을 설정하고,

**원하는 메뉴 선택 → AI 식단 생성 → 영양 기준 판정 → 자동 재조정 → 맞춤 레시피 제공**

과정을 하나의 서비스로 연결했습니다.

### 핵심 기능

| 기능           | 설명                                      |
| ------------ | --------------------------------------- |
| 🎯 개인 영양 기준  | 성별·키를 기반으로 기본 영양 기준을 산출하고 필요 시 개인 목표 설정 |
| 🍳 메뉴·재료 지정  | 원하는 메뉴 또는 보유 재료를 반영한 한 끼 생성             |
| 🤖 AI 식단 생성  | 식사 데이터를 학습한 생성 모델로 한 끼 메뉴 구성            |
| 📊 영양 적합성 판정 | 열량·단백질·칼륨·인·나트륨을 개인 기준과 비교              |
| 🎛️ 자동 재조정   | 기준을 벗어난 메뉴·재료·섭취량을 단계적으로 조정             |
| 📝 레시피 재구성   | 최종 재료와 중량에 맞춰 조리과정 재작성                  |
| 🔊 음성 안내     | 조리 단계를 음성으로 안내                          |
| 📄 PDF 저장    | 최종 식단과 레시피 저장                           |
| 📅 식사 기록     | 날짜·끼니별 기록과 하루 누적 영양량 확인                 |
| 💬 영양 상담     | 근거 자료와 영양 DB를 활용한 식이 관련 질의응답            |

## 🤖 AI · RULE · LLM

FOOK은 모든 판단을 하나의 AI 모델에 맡기지 않고,
**생성·검증·설명의 역할을 분리**했습니다.

```text
사용자 조건 · 요청
        │
        ▼
AI 식단 생성
Seq2Seq + Attention
        │
        ▼
5대 영양소 기준 판정
        │
        ▼
RULE 기반 재조정
메뉴 · 재료 · 중량 보정
        │
        ▼
최종 영양 기준 재검증
        │
        ▼
LLM 레시피 재구성
        │
        ▼
맞춤형 한 끼 제공
```

| 영역       | 역할                                |
| -------- | --------------------------------- |
| **AI**   | 다양한 식사 데이터를 기반으로 한 끼 메뉴 조합 생성     |
| **RULE** | 영양 기준에 따라 초과·부족 여부를 판정하고 재료·중량 보정 |
| **LLM**  | 확정된 메뉴·재료·중량을 바탕으로 조리과정 작성        |

영양 수치와 적합성 판정을 LLM에게 맡기지 않고,
**계산 가능한 영양 기준은 코드로 검증하고 LLM은 조리 텍스트 생성에 활용**했습니다.

## 🎛️ 영양 보정 구조

AI가 생성한 식단이 처음부터 모든 기준을 충족하지 않을 수 있기 때문에
생성 결과를 다시 계산하고 단계적으로 보정합니다.

```text
식단 생성
   ↓
5가지 영양 기준 확인
   ↓
기준 미충족
   ↓
메뉴 · 재료 · 중량 조정
   ↓
영양성분 재계산
   ↓
최종 기준 확인
```

주요 보정 대상은 다음과 같습니다.

* 김치 및 고나트륨 식품 조정
* 조미료 나트륨 감량
* 고칼륨 식재료 및 섭취량 조정
* 고인 식품 조정
* 단백질 부족·초과 보정
* 열량 부족 보완

한 영양소의 조정이 다른 영양소에 미치는 영향을 고려해
**영향 범위에 따라 보정 순서를 설계**했습니다.

## 📊 검증 결과

신체조건과 사용자 요청을 다르게 구성한 **120개 시나리오**로
실제 서비스와 동일한 방식의 식단 생성 결과를 검증했습니다.

| 평가 항목            |          결과 |
| ---------------- | ----------: |
| 5가지 영양 기준 충족률    |   **90.8%** |
| 사용자 지정 메뉴·재료 반영률 |   **94.7%** |
| 최종 식단 추천 성공률     |   **89.2%** |
| 식품영양학 박사 전문가 평가  | **4.2 / 5** |

전문가 검토에서는 대표 식단 8개 모두 영양 기준을 충족했으며,
일부 메뉴 조화·식재료 반복·조리 현실성은 추가 개선 영역으로 확인했습니다.

## 🛡️ 안전성·보안 및 오류 대응

### 계정·사용자 데이터 보호

* 계정·신체정보·식사기록 등 서비스 제공에 필요한 정보를 저장하며, **혈액검사 결과나 병원 의료정보는 직접 연계하지 않습니다.**
* 비밀번호는 **PBKDF2-SHA256 + Random Salt**로 해싱하고 세션 토큰도 Hash 형태로 저장합니다.
* 사용자 데이터는 인증된 계정별로 분리하며, API Key·DB 접속정보는 환경변수로 관리하고 Repository에서 제외합니다.

### 식이 정보 안전성

* **식단 생성·영양 검증과 LLM 레시피 생성을 분리**해 LLM이 영양 적합성을 직접 판단하지 않도록 설계했습니다.
* 재료·중량 조정 후 5대 영양소를 다시 계산하며, 기준을 충족하지 못하면 **미충족 항목과 주의사항을 함께 안내**합니다.

### 시스템 오류 대응

* 서버 지연·연결 실패 시 Timeout과 상황에 맞는 오류 안내를 제공합니다.
* 서버 저장 실패 시 식사기록 등은 **현재 브라우저에 임시 보존**해 일시적인 연결 오류로 데이터가 바로 사라지지 않도록 했습니다.
* AI 생성 모델의 동시 요청 오류를 방지하기 위해 **Lock과 초기 Warm-up**을 적용했습니다.

## ⚠️ 서비스 범위 및 한계

FOOK은 혈액투석 환자의 식사 결정을 돕기 위한 **식이관리 프로토타입**입니다.

* 의료진의 진단이나 처방을 대체하지 않습니다.
* 실제 혈액검사 수치를 직접 반영하지 않습니다.
* 기본 영양 기준은 신체정보를 기반으로 산출하며 사용자가 별도 목표값을 설정할 수 있습니다.
* 개인의 검사 결과와 치료 상태에 따라 적절한 식이 기준이 달라질 수 있으므로 실제 식이요법은 담당 의료진 또는 임상영양사와의 상담이 필요합니다.
